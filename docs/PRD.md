## 1. 产品概述

### 1.1 一句话定位

MealCompass 根据用户的**食材库存、时间、厨具、口味偏好、忌口**，推荐今天吃什么/做什么，并生成步骤、替代食材与购物清单。

### 1.2 问题与机会

| 痛点           | 现状                    | MealCompass 的解法      |
| -------------- | ----------------------- | ----------------------- |
| 不知道吃什么   | 随机转盘、拍脑袋        | 多约束检索 + Agent 推荐 |
| 有忌口/过敏的人怕踩雷 | 通用 App 只按关键词搜，不看忌口 | 忌口硬约束（规则引擎）  |
| 有食材不会用   | 需要自己想              | 冰箱食材反向检索        |
| 做菜中途要查   | 手上有油翻手机          | 烹饪指导模式 + 语音     |

### 1.3 目标用户

| 用户 / 场景 | 核心诉求 | 优先级 |
| --------------- | ------------------ | ------ |
| 做饭的普通人（一人食 / 家庭） | 快手、好吃、少浪费 | MVP    |
| 有忌口或过敏的人 | 绝不推荐踩雷食材 | MVP    |
| 有明确厨具 / 时间限制的人 | 只推做得到的菜 | MVP    |
| 想吃得轻负担的人 | 看到预估热量、可选少油少盐排序 | P1     |

> 产品面向**所有普通人**，不做医学人群细分。约束来自用户自己的忌口、可用时间、可用厨具与口味偏好，见 §2.2。

### 1.4 产品目标与成功指标

> ⚠️ **2026-10-11 修订（v1.2）**：原表只有「目标值」一列，读者会以为已经达成。现补「实测值」列，**不达标就写不达标**。

| 目标     | 指标                    | 目标值    | **实测值（2026-10-11）** |
| -------- | ----------------------- | --------- | ----------------------- |
| 检索质量 | Recall@5                | ≥ 85%    | **63.75%**（纯向量，40 条评估集）——**未达标**；差距归因见 `README.md`（主要是标注不完整 + `time_minutes` 全 NULL） |
| 约束满足 | 硬约束满足率            | = 100%    | **100%**。硬约束下推到 SQL `WHERE`，无候选时返回 `no_solution_reason` 而不是违规菜谱 |
| 推荐质量 | 用户采纳率（收藏/做过） | ≥ 30%    | **未测量**（无用户，无埋点） |
| 性能     | P95 响应延迟            | ≤ 3s     | **未达标**：`/recommend` 端到端 9–12 s（`parse` + `generate` 两次串行 chat）；**纯检索 P95 = 859 ms 达标** |
| 成本     | 单次推荐 Token 成本     | ≤ ¥0.05 | **未计**（Langfuse 已记录 `usage_details`，但没有做成本对账） |
| 工程质量 | 单元测试覆盖率          | ≥ 70%    | **96%**（生产代码口径，519 passed / 4 skipped）——**达标** |

> **「Recall@5 ≥ 85%」这个目标值现已从结论口径中删除**：它是拍出来的、没有测量支撑的，实测 63.75%。README 早期版本拿它当过结论，是本次修订要修掉的问题。

### 1.5 非目标（明确不做）

- ❌ 不做医疗诊断或治疗建议
- ❌ 不做外卖/电商下单
- ❌ 不做 UGC 菜谱社区
- ❌ 不做第三方登录（OAuth），MVP 仅邮箱 + JWT
- ❌ 不做医学人群细分，也不做 GI / 钠 / 蛋白质等医学营养数值约束（数据不可得，且不构成医学建议）
- ❌ 不做多智能体复杂协作（单主 Agent 足够）
- ❌ 不做移动端原生 App（只做响应式 Web）
- ❌ 不做实时视频烹饪教学

## 2. 用户画像与约束模型

### 2.1 画像数据结构

```python
UserProfile:
  user_id: str
  taste_preferences: str[]    # 辣度、清淡/重口、菜系偏好
  hard_constraints: Rule[]    # 硬约束，必须满足：忌口/过敏、时间、厨具
  soft_preferences: Rule[]    # 软偏好，影响排序
  tools_available: str[]      # 可用厨具
  skill_level: enum           # 新手 / 熟练
  servings: int               # 常做份量
```

### 2.2 约束类型矩阵

| 类型   | 约束                     | 判定方式           | 数据来源          |
| ------ | ------------------------ | ------------------ | ----------------- |
| 硬约束 | 忌口 / 过敏原（食材级）  | 规则引擎，命中即过滤 | 食材同义词表      |
| 硬约束 | 可用时间上限             | 规则引擎，下推检索 | 菜谱耗时字段      |
| 硬约束 | 可用厨具                 | 规则引擎，下推检索 | 菜谱工具字段      |
| 软偏好 | 辣度 / 清淡 / 菜系       | 规则引擎加分排序   | 菜谱标签          |
| 软偏好 | 少油 / 少盐 / 低卡       | 规则引擎加分排序   | 预估热量 + 标签   |

### 2.3 规则引擎设计

- 规则以 **YAML 配置**，非技术人员可维护
- 每条规则实现 `evaluate(recipe, profile) -> RuleResult`
- 硬约束失败 → 直接过滤；软偏好失败 → 降权排序
- **LLM 不参与硬约束判断**，仅规则引擎判定

**DoD：**

- [ ] 新增一条约束只需添加 1 个 rules YAML 条目，**零代码改动**
- [ ] 规则引擎有单元测试，覆盖每个规则的正反用例
- [ ] 硬约束冲突时（如无解），系统返回"无匹配 + 放宽建议"，不返回违规菜谱

### 模块 C：Agent 与推荐

#### F-C1 查询理解 `[MVP]`

- 描述：LLM 输出结构化 JSON（意图、食材、约束、目标）
- **DoD：**
  - [ ] 输出符合 Pydantic schema，解析失败自动重试 ≤ 2 次
  - [ ] 抽取字段准确率 ≥ 90%（评估集）
  - [ ] 信息不足时触发澄清追问（见 F-C2）

#### F-C2 澄清追问 `[MVP]`

- 描述：信息不足时主动问，而非瞎猜
- **DoD：**
  - [ ] 缺失关键约束（如忌口、可用时间）时追问
  - [ ] 追问不超过 2 轮，避免用户烦躁
  - [ ] 用户可跳过，系统用默认值继续

#### F-C3 推荐生成 `[MVP]`

- 描述：输出 3 道菜 + 理由 + 缺失食材 + 替代方案
- **DoD：**
  - [ ] 固定输出 3 道（可配置）
  - [ ] 每道含：菜名、匹配理由、缺失食材、替代方案、耗时
  - [ ] 理由必须引用用户输入的具体约束
  - [ ] 输出 JSON 可被前端直接渲染

#### F-C4 反思校验 `[MVP]`

- 描述：生成后自我检查，违规则重试
- **DoD：**
  - [ ] 校验过敏原、时间、厨具、热量四类硬约束
  - [ ] 违规时重试 ≤ 2 次，仍失败则降级返回安全候选
  - [ ] 校验失败率、重试次数写入 Langfuse

#### F-C5 工具调用 `[MVP]`

- 描述：Agent 可调用检索、详情、替代、缩放、购物清单等工具
- **DoD：**
  - [ ] 工具以注册表管理，新增工具零改主流程
  - [ ] 工具调用失败有兜底（超时、异常、空结果）
  - [ ] 工具调用链在 Langfuse 可视化

#### F-C6 状态机编排 `[MVP]`

- 描述：LangGraph 定义节点与条件边
- **DoD：**
  - [ ] 状态含：消息、画像、约束、候选、选中、步骤
  - [ ] 节点：parse → clarify → search → filter → rank → reflect → output
  - [ ] 支持中断恢复（会话持久化）

#### F-C7 多轮对话 `[P1]`

- 描述：支持"换一个""这道怎么做""没有料酒怎么办"
- **DoD：**
  - [ ] 上下文保持 ≥ 10 轮
  - [ ] 指代消解正确（"它""这道"）
  - [ ] 切换话题不丢失画像

## 4. 用户流程

### 4.1 主流程：首次推荐

```
访问 → 注册/登录 → 引导设置画像 → 输入需求
  → Agent 解析 → (信息不足? 澄清追问)
  → 混合检索 → 硬约束过滤 → 重排
  → 生成 3 道推荐 → 反思校验 → 展示
  → 用户选择 → 菜谱详情 → 加入购物清单
```

### 4.2 主流程：烹饪指导

```
选中菜谱 → 进入烹饪模式 → 分步展示
  → 计时器/语音 → 追问（替代食材）
  → 完成 → 反馈（做过/评分）
```

### 4.3 主流程：一周规划 `[P1]`

```
设置目标（份量/预算）→ Agent 生成 7 天菜单
  → 用户调整 → 生成购物清单 → 导出
```

### 4.4 异常流程

| 场景         | 处理                         |
| ------------ | ---------------------------- |
| 检索为空     | 提示放宽约束，给替代方案     |
| 硬约束无解   | 返回"无匹配"+ 建议放宽项     |
| LLM 超时     | 降级返回缓存/规则候选        |
| 规则冲突     | 优先级：过敏 > 疾病 > 偏好   |
| 用户跳过画像 | 默认 general，推荐后引导补充 |
