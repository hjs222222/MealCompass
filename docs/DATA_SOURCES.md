### 目录结构

配图与对应菜谱**放在同一目录**，markdown 里用相对路径引用（如 `![成品](./成品.jpg)`），
所以镜像上游结构即可保证引用不失效：

```
data/raw/howtocook/
├── aquatic/  breakfast/  condiment/  dessert/  drink/
├── meat_dish/  semi-finished/  soup/  staple/  vegetable_dish/
│   ├── 上汤娃娃菜/
│   │   ├── 上汤娃娃菜.md      ← 菜谱
│   │   └── 上汤娃娃菜.png     ← 成品配图（127 KB）
│   └── 葱烧鸡腿.md            ← 部分菜谱是扁平结构，无配图
└── LICENSE
```

- **177 / 372 道菜有配图**，共 346 条本地引用；另有 2 条外链图（上游托管在 GitHub user-images，未下载）。
- 354 张图里有 8 张没有被任何菜谱引用（上游遗留）。
- 部分文件名含括号（如 `石凉粉(冰粉)成品1.jpg`），解析器已按 markdown 语法正确处理，**0 缺失**。

### 解析层的「噪声清理」（2026-10-11，C5）

第一版解析器把**章节小标题、整句说明、缩放规则、工具名**都当成了食材，这些噪声让归一化率的
分母是虚高的，也污染了 `unmapped_top`。清理规则（全部有单测，见
`backend/tests/unit/test_import_howtocook.py`）：

| 噪声类型 | 真实样本 | 处理 |
| --- | --- | --- |
| 章节小标题 | `工具`、`原料:`、`食材`、`调料` | 丢弃（**既不算食材也不算厨具**） |
| 用量说明句 | `盐的用量为 3 g/人`、`一碗容量是 500ml。` | 丢弃 |
| 整句说明 | `一般一个人可以食用 60ml-110ml 的米。`、`非黑暗料理🍆` | 丢弃 |
| **缩放规则** | `肉量 = 份数 * 200g。` | 丢弃（右侧是 `份数` 变量，不是一份食材清单） |
| 工具 / 耗材 | `厨房纸`、`水果刀`、`手动压汁器`、`盆`、`小碗` | 归 `recipe.tools`，不进食材表 |
| 并列写法 | `葱、姜、蒜`、`小葱/大葱/洋葱总量` | **拆分**成多味（拆开才能各自归一化；平分用量等于编造数字，所以不给每味摊派用量） |
| 虚词 | `一般`、`左右` | 丢弃 |
| **反例（必须保留）** | `盐量`、`肉量`、`油量`（`盐量 = 兔肉斤数 * 2 克`） | 「量」结尾不等于说明句，**不能一刀切误杀** |

**清理前后的真实对比**（两份报告都已**入库**，可直接对账：[`docs/evidence/import_report.before.json`](./evidence/import_report.before.json) / [`import_report.after.json`](./evidence/import_report.after.json)）：

| 指标 | 清理前 | 清理后 | 变化 |
| --- | --- | --- | --- |
| 食材条目 | 3,902 | **3,697** | −205（垃圾行不再进表） |
| 去重种数 | 1,394 | **1,162** | −232 |
| 归一化率 | 73.5% | **75.3%** | **+1.8pp** |
| 未收录种数 | 856 | **748** | −108 |
| 用量待确认 | 86 | **25** | −61 |
| `unmapped_top` 里的噪声 | `工具`(5)、`手动压汁器`(4)、`厨房纸`(3)、`盐的用量为`(3)… | **全部消失** | — |

> **为什么归一化率会「上升」**：分母里的垃圾少了、未收录的噪声名少了，而真食材的命中数基本不变
> （2,867 → 2,784，降的是那批被误当食材的说明行）。这不是把词表塞大来刷指标——**词表一个词都没加**。

### 已知的数据缺口

- **没有 `time_minutes`（烹饪耗时）**：`recipes.time_minutes` **372 行全为 NULL**——上游不提供。这是硬约束字段，**不得编造**；`recipes.tools` 只有 82 行非空。二者直接导致「场景 / 耗时」类查询的 Recall@5 只有 16.7%–20.8%（详见 `README.md` 结论四）。
- **只有热量，没有蛋白质 / GI / 钠**：这正是本项目**不做医学人群细分**的原因（见 `README.md` 全局约定与 `PRD.md` §1.5）。
- 用量写法不统一，解析器对「解析不出」的行保留原文而不是猜（见 `import_report.json`；当前 **25 条**）。
- 372 道菜里 177 道有配图，其余 195 道前端详情页需要占位图兜底。
