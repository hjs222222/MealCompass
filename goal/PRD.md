## 1. 产品概述

### 1.1 一句话定位

MealCompass 根据用户的**食材库存、时间、厨具、健康画像、忌口**，推荐今天吃什么/做什么，并生成步骤、替代食材与购物清单。

### 1.2 问题与机会

| 痛点           | 现状                    | MealCompass 的解法      |
| -------------- | ----------------------- | ----------------------- |
| 不知道吃什么   | 随机转盘、拍脑袋        | 多约束检索 + Agent 推荐 |
| 健康人群难选菜 | 通用菜谱 App 无医学约束 | 人群画像 + 规则引擎     |
| 有食材不会用   | 需要自己想              | 冰箱食材反向检索        |
| 做菜中途要查   | 手上有油翻手机          | 烹饪指导模式 + 语音     |

### 1.3 目标用户

| 人群            | 核心诉求           | 优先级 |
| --------------- | ------------------ | ------ |
| 普通家庭用户    | 快手、好吃、少浪费 | MVP    |
| 健身人群        | 高蛋白、控热量     | MVP    |
| 糖尿病/控糖人群 | 低 GI、控碳水      | MVP    |
| 儿童家长        | 无过敏原、营养均衡 | P1     |
| 高血压人群      | 低钠               | P1     |
| 孕妇            | 禁忌食材、叶酸铁   | P2     |
| 痛风人群        | 低嘌呤             | P2     |

### 1.4 产品目标与成功指标

| 目标     | 指标                    | 目标值    |
| -------- | ----------------------- | --------- |
| 检索质量 | Recall@5                | ≥ 85%    |
| 约束满足 | 硬约束满足率            | = 100%    |
| 推荐质量 | 用户采纳率（收藏/做过） | ≥ 30%    |
| 性能     | P95 响应延迟            | ≤ 3s     |
| 成本     | 单次推荐 Token 成本     | ≤ ¥0.05 |
| 工程质量 | 单元测试覆盖率          | ≥ 70%    |

### 1.5 非目标（明确不做）

- ❌ 不做医疗诊断或治疗建议
- ❌ 不做外卖/电商下单
- ❌ 不做 UGC 菜谱社区
- ❌ 不做多智能体复杂协作（单主 Agent 足够）
- ❌ 不做移动端原生 App（只做响应式 Web）
- ❌ 不做实时视频烹饪教学

## 2. 人群画像与约束模型

### 2.1 画像数据结构

```python
UserProfile:
  user_id, cohort, goals[]
  hard_constraints: Rule[]    # 硬约束，必须满足
  soft_preferences: Rule[]    # 软偏好，影响排序
  nutrition_targets: dict     # 热量/蛋白/钠/GI
  tools_available: str[]
  skill_level: enum
```

### 2.2 人群约束矩阵

| 人群         | 硬约束               | 软偏好       | 知识来源      |
| ------------ | -------------------- | ------------ | ------------- |
| general      | 无                   | 口味、菜系   | 通用菜谱      |
| fitness      | 蛋白≥阈值、热量区间 | 高蛋白、低脂 | 运动营养      |
| diabetes     | GI、碳水、糖上限     | 低 GI、粗粮  | 食物成分表 GI |
| child        | 过敏原、年龄禁忌     | 趣味、口味   | 儿科营养指南  |
| hypertension | 钠上限               | 低盐、DASH   | DASH 指南     |

### 2.3 规则引擎设计

- 规则以 **YAML 配置**，非技术人员可维护
- 每条规则实现 `evaluate(recipe, profile) -> RuleResult`
- 硬约束失败 → 直接过滤；软偏好失败 → 降权排序
- **LLM 不参与硬约束判断**，仅规则引擎判定

**DoD：**

- [ ] 新增一个人群只需添加 1 个 profile + 1 个 rules YAML，**零代码改动**
- [ ] 规则引擎有单元测试，覆盖每个规则的正反用例
- [ ] 硬约束冲突时（如无解），系统返回"无匹配 + 放宽建议"，不返回违规菜谱

## 3. 功能列表与验收标准

### 模块 A：用户与画像

#### F-A1 注册 / 登录 `[MVP]`

- 描述：邮箱或第三方登录，JWT 鉴权
- **DoD：**
  - [ ] 支持注册、登录、登出、Token 刷新
  - [ ] 密码加密存储（bcrypt）
  - [ ] 未登录访问受保护页面自动跳转登录
  - [ ] 多用户数据完全隔离（越权测试通过）

#### F-A2 画像设置 `[MVP]`

- 描述：用户选择人群、目标、忌口、厨具、技能
- **DoD：**
  - [ ] 首次登录引导完成画像（可跳过，默认 general）
  - [ ] 画像可随时编辑并立即生效
  - [ ] 画像变更后推荐结果随之变化（可验证）
  - [ ] 过敏原/禁忌为多选，且不可为空提交（若选了特殊人群）

#### F-A3 长期记忆 `[P1]`

- 描述：记住用户偏好、历史评分、常做菜
- **DoD：**
  - [ ] 记录用户点赞/踩/收藏/做过
  - [ ] 推荐时读取历史，避免重复推荐已踩菜品
  - [ ] 用户可查看并清除记忆数据（隐私合规）

### 模块 B：知识库与 RAG

#### F-B1 菜谱知识库构建 `[MVP]`

- 描述：结构化 200+ 菜谱，含食材、步骤、营养、工具
- **DoD：**
  - [ ] 至少 200 道结构化菜谱入库
  - [ ] 每条菜谱含完整 schema（见 1.2 节字段）
  - [ ] 食材已归一化（番茄=西红柿）
  - [ ] 营养字段缺失率 ≤ 20%（缺失需标注，不可编造）

#### F-B2 双层切分与索引 `[MVP]`

- 描述：菜谱卡片 + 步骤块分别索引
- **DoD：**
  - [ ] 卡片级与步骤级分别建索引
  - [ ] 检索先召回卡片，再取步骤详情
  - [ ] 单条上下文不超过模型上下文窗口的 60%

#### F-B3 混合检索 `[MVP]`

- 描述：向量（BGE-M3）+ BM25，RRF 融合
- **DoD：**
  - [ ] 向量与关键词各召回 Top 50
  - [ ] RRF 融合后 Top 10 进入重排
  - [ ] Recall@5 ≥ 85%（在评估集上）
  - [ ] 提供消融对比：纯向量 vs 混合（写入 README）

#### F-B4 重排 `[MVP]`

- 描述：bge-reranker-v2-m3 重排
- **DoD：**
  - [ ] 重排后 nDCG@5 相比未重排提升 ≥ 10%
  - [ ] 重排延迟 ≤ 500ms（Top 10）

#### F-B5 元数据过滤下推 `[MVP]`

- 描述：硬约束在检索层过滤，不检索后再过滤
- **DoD：**
  - [ ] 时间、厨具、忌口等硬约束下推至 SQL/向量查询
  - [ ] 过滤后结果集非空；若为空，触发放宽策略并提示用户

#### F-B6 引用与防幻觉 `[MVP]`

- 描述：生成内容必须引用真实 recipe_id
- **DoD：**
  - [ ] 每条推荐附带 recipe_id，可点击查看原菜谱
  - [ ] 生成内容不含知识库外的食材/步骤
  - [ ] 引用准确率 ≥ 95%（人工抽检 50 条）

### 模块 C：Agent 与推荐

#### F-C1 查询理解 `[MVP]`

- 描述：LLM 输出结构化 JSON（意图、食材、约束、目标）
- **DoD：**
  - [ ] 输出符合 Pydantic schema，解析失败自动重试 ≤ 2 次
  - [ ] 抽取字段准确率 ≥ 90%（评估集）
  - [ ] 信息不足时触发澄清追问（见 F-C2）

#### F-C2 澄清追问 `[MVP]`

- 描述：信息不足时主动问，而非瞎猜
- **DoD：**
  - [ ] 缺失关键约束（如人群、时间）时追问
  - [ ] 追问不超过 2 轮，避免用户烦躁
  - [ ] 用户可跳过，系统用默认值继续

#### F-C3 推荐生成 `[MVP]`

- 描述：输出 3 道菜 + 理由 + 缺失食材 + 替代方案
- **DoD：**
  - [ ] 固定输出 3 道（可配置）
  - [ ] 每道含：菜名、匹配理由、缺失食材、替代方案、耗时
  - [ ] 理由必须引用用户输入的具体约束
  - [ ] 输出 JSON 可被前端直接渲染

#### F-C4 反思校验 `[MVP]`

- 描述：生成后自我检查，违规则重试
- **DoD：**
  - [ ] 校验过敏原、时间、厨具、热量四类硬约束
  - [ ] 违规时重试 ≤ 2 次，仍失败则降级返回安全候选
  - [ ] 校验失败率、重试次数写入 Langfuse

#### F-C5 工具调用 `[MVP]`

- 描述：Agent 可调用检索、详情、替代、缩放、购物清单等工具
- **DoD：**
  - [ ] 工具以注册表管理，新增工具零改主流程
  - [ ] 工具调用失败有兜底（超时、异常、空结果）
  - [ ] 工具调用链在 Langfuse 可视化

#### F-C6 状态机编排 `[MVP]`

- 描述：LangGraph 定义节点与条件边
- **DoD：**
  - [ ] 状态含：消息、画像、约束、候选、选中、步骤
  - [ ] 节点：parse → clarify → search → filter → rank → reflect → output
  - [ ] 支持中断恢复（会话持久化）

#### F-C7 多轮对话 `[P1]`

- 描述：支持"换一个""这道怎么做""没有料酒怎么办"
- **DoD：**
  - [ ] 上下文保持 ≥ 10 轮
  - [ ] 指代消解正确（"它""这道"）
  - [ ] 切换话题不丢失画像

## 4. 用户流程

### 4.1 主流程：首次推荐

```
访问 → 注册/登录 → 引导设置画像 → 输入需求
  → Agent 解析 → (信息不足? 澄清追问)
  → 混合检索 → 硬约束过滤 → 重排
  → 生成 3 道推荐 → 反思校验 → 展示
  → 用户选择 → 菜谱详情 → 加入购物清单
```

### 4.2 主流程：烹饪指导

```
选中菜谱 → 进入烹饪模式 → 分步展示
  → 计时器/语音 → 追问（替代食材）
  → 完成 → 反馈（做过/评分）
```

### 4.3 主流程：一周规划 `[P1]`

```
设置目标（营养/预算）→ Agent 生成 7 天菜单
  → 用户调整 → 生成购物清单 → 导出
```

### 4.4 异常流程

| 场景         | 处理                         |
| ------------ | ---------------------------- |
| 检索为空     | 提示放宽约束，给替代方案     |
| 硬约束无解   | 返回"无匹配"+ 建议放宽项     |
| LLM 超时     | 降级返回缓存/规则候选        |
| 规则冲突     | 优先级：过敏 > 疾病 > 偏好   |
| 用户跳过画像 | 默认 general，推荐后引导补充 |
